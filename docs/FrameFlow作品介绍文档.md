# 使用方法

### 运行环境与首次配置

成品运行包适用于 Windows x64。数据库使用 MySQL 8.x，由部署环境自行安装并启动。Java、Nginx 和 FFmpeg 已随包提供，部署时保留运行包的完整目录结构。

1. 在 `config/database.properties` 填写数据库主机、端口、数据库名称、用户名和密码。默认库名为 `frameflow`；首次启动自动创建数据库，并由 Flyway 执行建表迁移，同时创建默认账号 `admin`，初始密码为 `Aa018779`。首次连接的数据库账号应具备相应建库、建表权限。
2. 如需开放新账号注册，在 `config/mail.properties` 填写 SMTP 主机、端口、发信邮箱、授权码和发件地址，配置完成后将 `REGISTRATION_MAIL_ENABLED` 设为 `true`。当前注册流程使用邮箱验证码；使用默认账号登录不依赖 SMTP。
3. 在 `config/launcher.json` 设置访问地址和端口。默认网页入口为 `127.0.0.1:8088`，后端内部端口为 `18081`。数据库端口与网站端口分别配置，互不替代。
4. 双击 `启动.cmd` 或 `Start.cmd`。脚本检查运行文件、配置和端口，启动后端，等待其就绪后启动 Nginx，并按配置自动打开浏览器。
5. 浏览器访问 `http://127.0.0.1:8088`，使用默认账号 `admin` 和密码 `Aa018779` 登录后进入工作台；也可通过邮箱验证码注册独立账号。

各启动文件的作用如下。

| 文件 | 使用方式 |
| --- | --- |
| `启动.cmd` / `Start.cmd` | 启动整套服务并按配置打开浏览器。 |
| `Stop.cmd` | 停止该运行包的后端与 Nginx，不停止外部 MySQL 服务。 |
| `Status.cmd` | 查看该运行包的服务状态。 |
| `Check.cmd` | 预检查工具文件、Java 运行环境及端口占用。数据库连接在实际启动时验证。 |

数据库、邮箱及启动配置修改后，通过停止、重新启动服务使其生效。日志位于 `logs`；数据库认证失败、端口冲突或工具文件缺失均会给出启动错误提示。

### 网络访问与模型配置

本机测试采用默认地址。局域网访问时，将 `listenAddress` 改为 `0.0.0.0`，放行对应网页端口后，通过部署机器的实际局域网 IP 访问。内网穿透的本地目标指向 `127.0.0.1:8088`。对外提供服务时以 Nginx 或其他 TLS 入口配置 HTTPS，并配套启用安全 Cookie 和受信代理设置。

常规媒体处理不需要第三方 AI 凭据。使用云端文字能力或语音识别时，在网站设置中选择对应服务商、模型并填写个人凭据；模型选项提供预设与自定义入口，实际可用性取决于供应商接口、账号权限和模型能力。相关调用前显示服务来源及确认提示，配置或调用失败时给出相应说明。

服务端本地模型接入功能已实现，可作为云端文字服务之外的推理方式。本次提交未包含本地模型权重文件；启用时，由部署端另行准备兼容模型，启动 llama.cpp 推理服务并加载模型，再启用后端对应配置。浏览器访问者无需在个人设备安装模型。成品运行包默认关闭本地模型接入，常规处理功能不受影响。

### 工作台操作流程

工作台左侧划分为“常规处理”“AI 协作处理”“历史记录”，各分类的子功能位于顶部横向标签栏。处理工具按“导入—编辑—导出”组织。

1. **导入素材。** 选择或拖入视频，系统上传文件并读取媒体规格。已有素材可从素材库继续使用。
2. **编辑处理参数。** 选择转换、压缩、音轨提取、裁切、同源片段拼接或静音；也可输入自然语言生成候选方案，或逐步填写处理步骤。
3. **确认并执行。** 明确参数后提交任务。AI 生成的内容先展示操作步骤和参数，确认后才进入处理队列。
4. **预览与导出。** 查看任务状态，播放浏览器兼容的结果并下载文件。无法直接播放的格式仍可下载。
5. **处理字幕。** 对含语音的素材选择识别服务，生成带时间戳的字幕；编辑、校对或翻译后，可导出 SRT 或烧录到视频。
6. **查看记录。** 在历史记录中查看任务及相关处理信息，按需展开详情、下载结果或删除记录。素材和结果提供相应删除入口。

默认单个上传文件上限为 3 GiB，媒体时长上限为 15 分钟。上传、识别及媒体处理还受各自的超时、容量和供应商限制约束。

## 一 项目详情及使用方式

### 项目定位

FrameFlow 是一个面向轻量音视频创作场景的网页工作台，将确定性的媒体处理与基于文字的智能协作结合。作品面向课程视频、演示录屏、访谈和短视频素材整理等需求，提供从素材导入、参数调整、字幕处理到结果导出的完整操作路径。

用户登录后直接选择工具，不需要先建立项目、分类或团队空间。素材、处理方案、任务、字幕与结果归属于当前账号，在服务端保存，支持跨页面继续操作及后续访问。

### 常规处理功能

| 功能 | 处理内容 | 输出或呈现 |
| --- | --- | --- |
| 视频检测 | 读取容器、时长、文件大小、分辨率、视频与音频编码、码率、帧率等媒体信息。 | 展示检测结果和预览兼容状态。 |
| 视频转换 | 根据媒体工具能力选择容器、编码及分辨率，按比例缩放。 | 支持 MP4、MOV、MKV、WebM 等视频容器，以及 H.264、HEVC、VP9、AV1 等编码的可用组合。 |
| 视频压缩 | 根据目标体积或导出参数调整编码设置。 | 生成经校验的结果，无法满足目标时明确报告失败。 |
| 提取音频 | 从视频中提取可用音轨。 | 独立音频文件；导出能力包含 MP3、M4A、WAV、FLAC。 |
| 视频裁切 | 按起止时间截取素材中的区间。 | 保留目标时段的视频文件。 |
| 片段拼接 | 选择同一素材中的多个区间，并按设定顺序拼接。 | 由所选区间组成的连续视频。 |
| 视频静音 | 移除视频音轨。 | 不含音轨的视频文件。 |
| 组合导出 | 在支持的参数组合中统一完成裁切、缩放、压缩或静音等操作，可另存音轨。 | 一个任务发布相应结果，减少中间文件的手动导入和下载。 |

导出选项根据部署环境的编码器能力开放，并校验容器与编码组合。分辨率支持保留原尺寸、常用预设及自定义边界框，保持原始比例，不将小尺寸素材放大。浏览器预览依据实际容器与编码判断，文件扩展名不作为唯一判断依据。

### 智能协作功能

**自然语言生成方案。** 输入“保留视频前 5 秒，缩小到 360p，并静音后导出 MP4”等处理要求，模型将需求转换为结构化候选参数。对缺少关键信息或存在歧义的要求，系统展示澄清问题；用户也可直接按顺序填写步骤。

**语音识别与字幕编辑。** 将素材音轨提交给所选语音识别服务，生成包含起止时间的字幕段。字幕支持编辑、版本保存与 SRT 导出，已有字幕可直接继续处理。

**字幕校对、翻译与双语字幕。** 文字模型对选中字幕提供校对建议，或分批翻译字幕内容。翻译过程保留字幕时间结构，支持单语与双语字幕导出及视频烧录，避免单独重新制作时间轴。

**按字幕找片段。** 对已保存的字幕提出查找要求，系统返回候选片段及对应原文和时间位置。结果可用于预览，并带入裁切或同源片段拼接操作。该能力依据字幕内容进行检索，不以画面视觉理解作为处理前提。

### 典型使用场景

课程录屏可先压缩和调整分辨率，再识别、校对字幕并生成带字幕的发布版本。访谈素材可先生成字幕，通过内容检索定位讨论片段，再选取区间进行裁切和拼接。跨语言内容可在已有字幕基础上翻译并导出双语 SRT，同时保留原始视频供后续使用。

## 二 项目亮点

### 轻量的使用路径

作品围绕单个素材及其处理任务组织流程。常规工具、智能协作和历史记录分组呈现，顶部功能标签与导入、编辑、导出阶段衔接，降低首次使用时的操作层级。素材预览、参数编辑和素材列表按区域组织，在对应桌面布局中独立滚动，减少查找和调整参数时的页面往返。

### 自然语言与明确参数共用执行能力

自然语言输入、分步填写和手动参数设置最终进入同一套方案校验与执行流程。连续处理通过有序步骤组合实现，执行器按操作类型调用已有能力，而不是为每一种操作组合建立独立业务流程。候选方案可检查、可修改，执行结果能够对应到具体参数。

### 可追溯的字幕检索

字幕检索结合中文分词、BM25 候选召回和模型筛选。返回结果关联原字幕段标识与时间范围，服务端复核引用是否来自本次候选、是否属于当前字幕版本。检索结果既是文字回答，也是可定位、可预览、可继续裁切的媒体区间。

### 清晰的处理来源

常规处理由部署机器上的 FFmpeg 完成，无需第三方模型调用。自然语言方案、字幕文字处理与语音识别分别使用相应模型服务。前端展示功能依赖、调用来源及不可用状态，用户能够区分媒体处理、文字推理和语音识别，按功能配置所需服务。

### 适应资源负载的任务调度

媒体处理使用后台队列，与网页请求解耦。调度器根据整机 CPU 和可用内存逐步调整新任务的准入与并发，低负载时提高吞吐，高负载时减少或暂停启动新任务。任务状态持久化，并结合执行租约、取消和中断处理，避免将长时间转码绑定在单次网页请求中。

### 可迁移的成品运行包

运行包同时携带 Java、媒体工具和代理程序，数据库及 SMTP 通过外部文件配置。首次启动自动建库、建表，启停脚本检查端口并识别自身进程；目录整体搬迁后，启动脚本重新生成实际路径配置，减少对开发环境和固定磁盘路径的依赖。

## 三 AI 测试技术落地使用情况概述

### 模型能力与业务场景的对应

| 业务场景 | 使用的模型能力 | 输入与结果 | 校验方式 |
| --- | --- | --- | --- |
| 自然语言处理方案 | 文字理解、结构化工具调用。 | 输入处理要求和必要媒体参数，输出候选步骤或澄清问题。 | 校验操作类型、参数、时长、能力与归属，确认后才执行。 |
| 语音转字幕 | 语音识别 ASR。 | 输入素材音轨，输出识别文字及句级时间信息。 | 校验响应结构、时间范围和字幕内容，失败不发布有效字幕。 |
| 字幕校对与翻译 | 文字校对、多语言翻译。 | 输入选定或分批字幕，输出建议或目标语言文本。 | 保持段标识和时间对应关系，校验输出结构并提供编辑确认。 |
| 字幕内容检索 | 检索增强生成 RAG。 | 输入查找要求与有限候选字幕，输出相关片段引用。 | 复核引用原文、段标识、时间范围及字幕版本。 |

文字服务适配 OpenAI、DeepSeek、阿里云百炼千问和豆包，并可接入部署端运行的千问模型。语音识别独立适配腾讯云及阿里云相关接口，包括千问语音、Fun-ASR 和 Paraformer 等已配置的模型选项。文字模型凭据与语音识别配置按对应接口分别使用。

方案生成、翻译和字幕检索以文字及必要媒体规格为输入，不向文字模型提交原始视频文件。语音识别处理提取的音轨。模型输出仅作为候选业务数据，不能直接成为操作系统命令、磁盘路径或任意网络地址。

### 标准工具调用的落地

云端方案生成采用 Function Calling 协议，向模型提供“提交媒体方案”和“请求澄清”两类受控工具。后端解析工具名称与结构化参数，拒绝未知工具、不完整响应、多个调用和不符合约束的字段。

本地模型接入采用受约束的 JSON 协议接收候选方案，随后执行相同的业务校验；该接入功能已实现，运行所需的模型权重未随本次作品上传。两种接入方式均由后端维护可执行操作集合，由用户确认决定是否创建处理任务。模型不直接获得 FFmpeg 命令执行权限。

### 字幕检索的落地

系统读取当前账号名下已保存的字幕快照，将相邻字幕分块并保留适量重叠，通过 Lucene 中文分词和 BM25 检索相关候选。模型只在受控的候选上下文中选择片段，后端恢复原字幕顺序，检查区间连续性及版本，再返回可定位的原文引用。

该机制限制一次推理的上下文规模，并保留结果与素材时间轴的联系。其召回依赖字幕文字及词汇匹配，原始识别错误、同义表达和字幕中未出现的画面信息仍可能影响结果；字幕编辑与人工确认用于修正实际内容。

### 测试组织与验证范围

自动化验证分为模型协议与边界测试、业务集成测试、前端交互测试和部署验证。模型接口使用受控响应覆盖成功、格式错误、超时、权限不足及服务不可用等情况，使同一业务条件能够重复验证；供应商的实际识别和生成效果取决于所选模型与素材。

| 验证层次 | 主要覆盖内容 |
| --- | --- |
| 模型协议与参数 | 工具名称、参数结构、澄清响应、未知操作、截断响应、云端失败分类及调用限制。 |
| 字幕检索与翻译 | 中文及混合文本、长字幕分块、候选预算、无命中、引用范围、版本失效和翻译段对应。 |

## 四 项目涉及的关键技术

### 前后端架构与接口契约

前端采用 Vue 3、TypeScript 和 Vite，按页面、交互组件、接口类型和业务协调组织代码。接口类型根据 OpenAPI 契约生成并检查，减少前后端对字段名称、状态和数据结构的理解差异。构建后的前端静态资源打入后端 JAR，通过同源入口访问接口。

后端采用 Java 21、Spring Boot、Spring Security、MyBatis 和 MySQL。请求按 Controller、Service 接口、Service 实现与 Mapper 分层：控制层处理请求和响应，业务层负责规则与事务，数据层集中维护 SQL。数据库结构由 Flyway 按版本迁移，支持首次部署建表与后续升级。

业务 JSON 响应统一使用 `Result<T>`，包含状态码、提示、数据、请求标识和字段错误详情。集中异常处理器处理业务及校验异常，安全过滤链输出一致的错误结构，并保留实际 HTTP 状态。视频、音频、字幕文件的成功响应使用文件流，以满足播放器和下载要求。

### 身份认证与凭据保护

账号密码采用带随机盐的 Argon2id 哈希保存。登录使用 Spring Session JDBC 管理的不透明会话标识，通过 HttpOnly Cookie 传输，由服务端检查有效性、到期时间及账号状态。写操作使用 CSRF 校验，退出撤销当前会话，修改密码和注销等操作撤销相应账号会话。

素材、方案、字幕、任务和结果均进行账号归属校验。个人云端 API 凭据使用 AES-256-GCM 加密存储，独立密钥保存在部署端文件中；密文与账号和供应商信息绑定。前端不将登录会话标识保存到浏览器本地存储。

### FFmpeg 进程调用与媒体校验

后端通过受控进程参数调用 FFmpeg 和 FFprobe，不经命令行解释器拼接用户输入。可执行文件路径由部署配置决定，处理时限制输入来源、协议、线程、运行时间和输出大小。转换完成后重新检测结果的时长、尺寸、编码和音轨，符合预期才发布。

播放接口先校验登录与文件归属，再提供支持 Range 的字节流，使兼容文件能够拖动播放。容器、视频编码、音频编码和浏览器解码能力共同决定预览可用性；不能直接预览的媒体给出提示，转换结果仍可按支持方式下载。

### 持久化任务与自适应并发

长时间媒体任务记录在数据库中，由后台执行器领取。状态覆盖等待、运行、取消中、成功、失败和已取消；通过条件更新、执行租约和版本约束，减少重复领取和过期执行者发布结果的风险。

默认从单任务并发开始，资源允许时逐步提升。自动并发上限按逻辑 CPU 数量计算，并限制在 1 至 4 之间；可通过部署参数调整。CPU 高于阈值或可用内存不足时停止准入新任务，已运行任务按自身超时与取消规则处理。该调控属于运行时准入管理，不等同于操作系统资源硬配额。

### 字幕数据与检索增强

字幕以带时间戳的分段数据保存，并维护版本信息。识别、编辑、校对、翻译、SRT 导出和字幕烧录围绕同一分段结构衔接，避免在不同功能之间丢失时间关联。

检索使用 Lucene SmartChinese 分词及 CJK 字词字段，按 BM25 相关度获取候选，再由文字模型筛选。返回结果携带字幕证据，业务层再次检查段标识、时间与当前版本。索引按请求隔离并释放，不共享跨账号字幕内容。

### 部署与配置管理

Nginx 作为统一网页入口转发页面、接口、上传和媒体请求。成品启动脚本根据外部配置生成匹配的代理端口与后端路径，并记录自身进程的身份信息。Java 运行环境及媒体工具随包交付，MySQL 和 SMTP 独立配置。

运行数据与程序文件分目录保存。数据库记录业务状态，磁盘保存素材和结果，独立密钥文件保护可解密的云端凭据。部署备份同时包含数据库、媒体存储和密钥，以维持账号数据、处理记录与文件之间的对应关系。
